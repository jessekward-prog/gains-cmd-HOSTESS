# Gains_CMD

A workout tracker built for the gym floor. Start a session and it walks you
through one set at a time: big steppers for weight and reps, rest in the card,
a hand-off screen between exercises, and a summary with your PRs when you finish.

- **Workout layouts:** Focus (one set at a time, swipe between sets and
  exercises), Dense (every set listed), Classic and Block Grid. Pick in Settings.
- **Special sets:** supersets (A → B → shared rest), drop sets, BFR timed sets,
  interval blocks with work/rest beeps, failure sets, variable sets, cardio with
  photo-of-the-screen stat capture.
- **Progression:** counts your sessions in rep range at each weight and tells you
  when to go up. This part is plain code, not AI. Assisted machines are handled
  the right way round: less counterweight is progress.
- **Exercise library:** 1,324 exercises with animations, steps and the muscles
  they work. Tap ⋯ → How to on any exercise in a workout. History shows a body map
  of the sets each muscle got this week. Your own exercise names stay as they are:
  Settings → Exercise library matches them to the library (exact spellings match
  themselves, the local model suggests the rest, and you can change any match).
  Data, animation and body-map credits are in [THIRD_PARTY.md](THIRD_PARTY.md).
- **Quest Mode:** tap Quest instead of Workout on the home screen to play that
  session as a pixel monster battler. Each exercise is a monster whose HP is the
  planned work, every set you log is an attack (kg × reps; bodyweight and assisted
  lifts hit for a flat 60 kg), rest is the monster catching its breath, and beating
  the top of your rep range is a crit. Clearing a quest banks XP toward levels,
  titles, pets and hero-card borders, opens a loot chest and earns a card pack for
  the dithered Card Vault (with a Forge for your own art). Progress is saved to the
  account. Sprite and art credits are in [THIRD_PARTY.md](THIRD_PARTY.md).
- **AI (optional):** a local model writes post-workout notes, answers in the Coach
  tab, builds programs in the AI Wizard and remixes workouts. Everything else
  works without it.
- **One PIN, no accounts:** single-user — the PIN is the only lock. Settings → Lock app brings it back.
- 26 themes, accent colours, font and text-size settings. Installs as a PWA.

## Running it on Hostess

Install it from the Hostess marketplace, or deploy this repo URL. Hostess builds
the `Dockerfile`, gives it a Postgres database (`postgres: true`) and wires your
local model in automatically.

On first launch you set a **PIN** (enter it twice) and you're in. There are no
accounts or passwords — it's one person's training log, and the PIN is the lock.

## Environment variables

All optional. Hostess fills in the first group itself.

| Variable | What it does |
|---|---|
| `DATABASE_URL` | Postgres connection. Set by Hostess (`postgres: true`). |
| `LM_STUDIO_URL`, `LM_STUDIO_API_KEY` | Your OpenAI-compatible local model endpoint. Set by Hostess from your library. Without them the AI features say they're unavailable and everything else works. |
| `LM_STUDIO_MODEL` | Model to request. Unset means "whatever the endpoint has loaded". Structured features (AI Wizard, Remix) work best on a 4B+ instruct model. |
| `SYNC_SECRET` | Lets Hostess read and change the AI link live (`GET/PUT /api/lm`) without a redeploy. Generated by Hostess. |
| `APP_PIN` | Preset the app PIN and skip the first-launch PIN screen. If set, it overrides a PIN chosen in the app. |
| `JWT_SECRET` | Session signing secret. Unset = one is generated on first boot and stored in the database. |
| `COOKIE_SECURE` | `true` to mark session cookies HTTPS-only. Leave unset when the app is reached over plain HTTP. |

## Developing

The source is kept flat: `src__components__Foo.jsx` is `src/components/Foo.jsx`.
`setup.sh` **moves** those files into `frontend/src/` before a build, so build in a
copy (or in Docker), never in your working tree:

```bash
docker build -t gains-cmd . && docker run -p 3001:3001 -e DATABASE_URL=... gains-cmd
```

Checks: `node focus.check.mjs` and `node supersets.check.mjs`.

Forgot the PIN? Set `APP_PIN` in the Hostess env panel and redeploy — it overrides
the stored one.
